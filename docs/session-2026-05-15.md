## What We Started With

A single-file prototype called **LifeLine** (`index.html`) — a financial advisor tool that overlaid client life milestones on a chart of US equity and bond market returns from 1926–2024. All data was hardcoded in script tags. No architecture for adding domains or swapping data contexts.

The user also arrived with a hand-crafted **Voting Rights domain JSON** — 34 events from 1865 to 2024, spanning Reconstruction amendments through Alexander v. South Carolina NAACP (2024), with magnitude and direction coded for each event, source URLs, provenance metadata, and a sample overlay for Alabama District 7. This JSON was the design north star for the domain data schema.

## What We Built

### Stratum — Historical Impact Overlay Engine

A React + Vite web application that renders interactive timeline charts overlaying consequential historical events against a time axis, with a user-defined personal or community overlay on top. The core principle: **the rendering engine is domain-agnostic**. It receives structured data objects and renders. Swapping domains means swapping datasets, not touching any rendering logic.

---

## Architecture

### Three Core Data Objects

```
DOMAIN        — config: time range, chart type, colors, labels, series definitions
EVENT         — a historical event: date, title, direction (expands/restricts/neutral), magnitude 1–10
OVERLAY_ENTRY — a user-added pin: date, title, value, note
```

### Three Chart Layers

| Layer | What it is | Who controls it |
|-------|-----------|-----------------|
| Layer 1 | Time axis | Renderer (always on) |
| Layer 2 | Domain events as vertical markers | Domain JSON |
| Layer 3 | User overlay entries as gold pins | User input / CSV import |

### Chart Types

The renderer reads `domain.chart_type` to determine the background layer:

- **`logarithmic_series`** — Multi-line log-scale chart (Financial Markets). Series values computed from annual returns, starting at $10,000.
- **`cumulative_impact`** — Running impact score computed from events (Voting Rights). Starts at 50, adds magnitude for `expands` events, subtracts for `restricts`. Rendered as a single colored line.

Both chart types share the same event marker and overlay pin drawing code.

## What's Running

### Two Fully Functional Domains

**Financial Markets** (`financial-markets.json`)
- 3 series: US Large Cap (S&P 500), Long-Term Bonds, T-Bills
- 99 years of annual returns (1926–2024)
- 21 historical events: crashes, expansions, Fed decisions
- Log-scale canvas rendering

**Voting Rights** (`voting-rights.json`)
- 34 events, 1865–2024
- From 13th Amendment ratification through Alexander v. South Carolina NAACP (2024)
- Includes Reconstruction era, Jim Crow, Civil Rights movement, and post-Shelby rollback
- Source URLs, tags, suggested overlay prompts, Alabama District 7 sample overlay
- Provenance metadata (55% human / 45% AI collaboration)
- Cumulative impact line rendering

### Packet System

A composable context layer architecture. Packets are self-contained JSON files in `src/data/packets/`. The app loads a packet registry and renders active packets as background layers behind the chart — domain-agnostic, togglable per session.

**Packet schema:**
```json
{
  "id": "packet-id",
  "type": "band | strip | event_stream | line",
  "time_range": { "start": 1789, "end": 2025 },
  "compatible_x_units": ["year"],
  "render": { "layer": "background", "opacity": 0.09 },
  "legend": [...],
  "data": [...]
}
```

**Packet registry** (`src/data/packets/registry.json`) — lists available packets. Sidebar filters to only show packets compatible with the active domain's time range.

**US Presidents packet** (`us-presidents.json`)
- All 44 administrations, 1789–2025
- Rendered as semi-transparent red (Republican) / blue (Democrat) / grey (other) bands behind the chart
- Labels appear horizontal if band is wide enough, rotated vertical if narrow
- Works on both domains (full Reconstruction-era coverage for Voting Rights)

## Design Decisions Made

| Decision | Rationale |
|----------|-----------|
| Canvas rendering (not D3) | Maximum control over custom markers, pins, and packet bands |
| Domain-agnostic renderer | Renderer reads `domain.chart_type`, `color_scheme`, `direction_labels` — never branches on `domain.id` |
| Packet registry pattern | Adding a new context layer = drop a JSON file. No code changes required |
| Cumulative impact line for voting rights | No continuous data series exists; derived line makes direction visible at a glance |
| Log scale for financial | $10K growing to $10M+ requires log scale to show early decades meaningfully |
| All domain data in local JSON | Structured so a backend or CMS can replace them later without touching the engine |

## Open Questions / Deferred

- **SCOTUS composition packet** — agreed to build next. Type: `strip`. Thin band at top of chart showing conservative/liberal ratio by year, keyed to major appointment events. Already in the packet registry architecture.
- **Packet "marketplace" vision** — user framed packets as injectable data modules that could be pulled from a remote registry. The local JSON structure already supports this; the `registry.json` could point to remote URLs instead of local files with minimal refactoring.
- **Domain-scoping for packets** — current filter is time-range intersection only. Future: packets could declare `compatible_domains: ["voting-rights"]` or `"*"` for global applicability.
